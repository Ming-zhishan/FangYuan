# 提交前的暂存内容审计

`node tools/audit-staged.mjs` 检查 **Git 暂存区将要提交的新增或修改内容**，不读取同名工作区文件。工具不连接 QQ、模型或生产数据库；也不自动修改、撤销或重新暂存文件。

在仓库根目录运行上述命令；从子目录调用时使用脚本的正确相对或绝对路径，工具会定位 Git 工作树根目录。Git 显式指定的 `GIT_INDEX_FILE` 同样适用，便于检查临时索引。

## 结果如何处理

| 退出码 | 含义 | 后续动作 |
| --- | --- | --- |
| `0` | 本次暂存变更未命中已有规则 | 继续人工审核真正的暂存差异；不是完整隐私或许可审查 |
| `1` | 有禁止路径或需要复核的内容/类型 | 逐项处理，修改后重新暂存并检查 |
| `2` | Git、对象读取或索引稳定性检查失败 | 先解决操作错误，再完整重跑；不能当作扫描通过 |

输出只包含规则类别、文件名和统计，不输出命中的原文。文件名使用转义表示，避免特殊字符打乱诊断。

## 范围与限制

- 检查禁止的运行/私人目录、环境文件和指定资产类型，以及已有凭据格式、私钥标记、账号形状数字和私人路径候选。`.env.example` 可作为模板，`.env.production` 等环境覆盖文件不允许。
- 冻结路径、模式和对象编号，直接读取不可变的 Git blob。审计结束再次比较暂存变更，发现变化则报错；不替代多人共享资源的写入协调。
- 重命名按删除加新增处理，检查目标内容；删除不重新扫描旧内容。该工具不扫描全部 Git 历史，也不证明当前公开树已彻底脱敏。
- 符号链接、子模块和未解决冲突要求复核，不跟随工作区链接。非 UTF-8、含空字节的内容要求复核；Git 单次输出超过工具的 16 MiB 限额或读取失败则报操作错误。
- 规则为启发式检测，可能误报或漏报。没有命中不能证明自定义 Token、私人内容、第三方许可或整个项目均无问题。
- 本次只落实本地检查和离线回归，尚未配置 GitHub 自动检查或分支保护；不要把可运行的脚本描述为合并前已强制执行。

## 回归入口

在仓库根目录运行：

```powershell
node --test tools/audit-staged.test.mjs
```

已纳入 `src/fangyuan-agent` 下的 `npm run test:repo`。测试使用独立临时 Git 仓库、生成的合成标记和空配置身份，不涉及真实凭据或账号，不更改用户的 Git 全局配置。覆盖暂存/工作区不一致、工作文件缺失、中文与空格路径、重命名、删除、路径门禁、特殊索引模式、编码、冲突、替代索引及读取失败。

旧实现仅按暂存文件名读取工作区，会漏检暂存内容或误报未暂存内容。本次回归先在旧实现复现四项失败，再验证修复；记录保留在本次 PR。仓库其他协作要求仍以 [CONTRIBUTING](../CONTRIBUTING.md) 和[安全发布闸门](../docs/SECURITY_RELEASE_GATE.md)为准。
