# 方源「戳一戳」轻互动 · 独立候选模块（默认关闭）

## 实际代码与边界

模块位于 `src/aurabot-modules/poke-interaction/`，由 `index.mjs` 和纯函数 `policy.mjs` 构成。直接复用 Aurabot 原生 `api.on('poke')` 事件及 `api.sendText`，**不新建 QQ 发信器、不接触记忆数据库、不调用模型、不使用未授权语音或表情素材**。

目前只是 Git 开发分支的源码，未被安装到真实 Aurabot 环境。模块的 `enabled` 与 `liveSend` 两个设置均默认 false；任意一个为 false，模块都不主动回复，也不接管原生 poke 事件。

## 可发送条件

只有同时满足下列条件时，才会发送一条短文字：

- QQ 插件总开关、`enabled`、`liveSend` 都明确开启；
- 真实 OneBot `notice / notify / poke`，戳的对象就是本 Bot；不是机器人自己、不是文字里的“戳一戳”；
- 限于 `allow.groups` 许可的群，不处理陌生群及私聊；
- 学习模块许可此群并提供近期会话框架，不处于闭嘴状态；
- 不是超过三分钟的旧事件；近期场景没有紧急求助或严重个人事件；
- 同群十五分钟冷却，同成员三十分钟冷却，同群每小时最多两条。

语气分为普通和熟悉两组原创短句（无需付费推理），关系参考只读取可公开的抽象关系类别；不读取或复述私人聊天来源。不能可靠判断时不发，严肃场景不利用彩蛋抢话。

发送前先在模块的私有数据目录保存尝试记录。即使网关返回错误或结果未知，也不会盲目重试；重启后冷却仍有效。模块无定时任务、无媒体自动发送、无外部 API。

## 离线验证

在仓库根目录执行：

```powershell
cd src/fangyuan-agent
npm test
```

测试包含错目标/错群、关闭开关、冷却与每小时上限、重启保留、并发重复通知、严重场景、状态损坏、发送结果不明等模拟事件。所有发送均为内存假对象，没有实际 QQ 发送。

## 上线前必须由用户验收

1. 先确定明确授权的测试群；在真实 QQ 网关只读确认 `botQQ`、`allow.groups` 与原生 poke 处理是否会冲突。
2. 将模块安装在有回滚备份的测试环境，先保持两个开关关闭，确认不会新增任何消息。
3. 用户批准一次真实 poke 测试后，才可开启双重开关；确认单条送达、原生模块不重复发、冷却正确，出现问题立即关闭。
4. 不将用户关系记录、QQ群号、真实事件日志或发言原文提交公开 Git。

此候选不修改核心人格体系，也不替换现有语音、梗图、主动发言和消息复核系统。
