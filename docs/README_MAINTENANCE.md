# README 维护与接任

本职责只维护项目介绍及其证据，不替代对话、多媒体和运行维护负责人的开发工作。开始前阅读根 README、CONTRIBUTING、SECURITY_RELEASE_GATE；多媒体状态另遵循 MEDIA_ENGINEERING_RULES。完整项目交接从[接任指南](MAINTAINER_HANDOFF.md)进入。

## 恢复工作

1. 阅读[当前工程状态](CURRENT_STATE.md)，取得最近核对日期、基线和待确认项；[首次 README 审查](README_AUDIT.md)仅作历史依据，不能当作最新状态。
2. 获取当前主分支，检查自该基线以来的提交、已合并 PR、相关未合并分支及对应测试记录。不能仅凭 PR 标题或旧报告更新状态。
3. 按下面的章节映射找出受影响段落。普通小修复不要求重写首页。
4. 专项维护在独立 `docs/*` 分支或工作树修改 README 与必要证据文档，不修改业务源码、数据库、生产配置或其他助手的未提交文件。功能负责人交付业务改动时，在其 PR 同步相应 README 与交接说明；需要文档维护者代写时，提供固定提交和证据，在该 PR 合并前完成核对。
5. 校验事实、链接、Markdown、Mermaid、隐私和差异；按仓库规范执行相关离线检查及 staged 审计。
6. 创建 PR 供用户审阅，说明验证与限制。合并、生产部署和公开媒体授权分别处理。

## 状态判断

每项重要声明记录日期、提交或文件、验证方法、结果和未覆盖范围。至少分别判断：

| 层次 | 足够的证据 | 不能据此推断 |
| --- | --- | --- |
| 愿景 | 用户确认的产品方向 | 已实现 |
| 代码 | 可定位实现及真实调用方 | 已测试、已启用 |
| 离线验证 | 明确命令、环境、结果与 fixture 范围 | 生产可用或真人满意 |
| 实际集成 | 固定宿主、接口与装载验证 | 真实 QQ 已送达 |
| 生产部署 | 版本、配置、装载或运行记录 | 接收效果合格 |
| 实际效果 | 授权目标的发送回执与接收侧体验验收 | 所有场景永久可靠 |

主分支是否包含和生产是否部署是两条独立状态。未合并但被单独部署的修复，应同时写明两者，并把部署结论标为对应验收记录所述。配置启用只说明配置意图，不证明进程装载或实际发送。

资料矛盾时保留差异：优先核对当前源码、配置、哈希和最新可靠验收；旧报告只作历史证据。无法核实时省略或明确标为待确认，不能补写推测。私人证据留在授权环境，公开文档只保存必要的脱敏结论。

## 章节与变更映射

| 变化 | 更新位置 | 主要依据 |
| --- | --- | --- |
| 人物定位或目标变化 | 首屏、设计理念 | 用户明确要求、人物卡和实际内核 |
| 新能力或弃用能力 | 核心能力、限制 | 实现、调用方、测试与验收 |
| 主要宿主、消息链路或网关变化 | 技术架构、技术栈 | 实际装载与调用证据 |
| 测试进入集成或生产 | 当前进展、证据文档 | 合并状态、部署及接收侧验收分别核对 |
| 目录、命令或协作规则变化 | 源码入口、开发入口 | 实际文件、package scripts、CONTRIBUTING |
| 新公开图片、音频或对话示例 | 适当的展示段落 | 来源、许可、隐私及展示范围确认 |
| 许可或发布边界变化 | 安全、许可与致谢 | 明确的许可文件和权属审查 |

首页只保留帮助读者判断阶段的信息，不反复同步素材总数、Token 数或大量测试统计。必须展示数字时附日期和验证范围。

## 校验与交付

- 每个 PR 填写 README 影响判断：受影响章节与证据页，或无需修改的具体理由。使用[PR 模板](../.github/pull_request_template.md)提醒后续接任者；模板不是自动语义校验，仍须人工核对。
- 对照源码与记录逐项检查能力声明；复核未合并 PR 的状态，使用固定提交保存历史依据。
- 检查相对链接、标题锚点、目录、表格、代码块和 Mermaid。宽表允许横向滚动，正文在窄屏应可读；本地预览不能冒称 GitHub 实际渲染验收。
- 默认离线检查入口是根目录 `npm run check`，Node 子集为根 `npm test`；原子目录命令继续兼容。沿用有效记录并清楚注明；没有新变更或失败原因时不反复运行全库测试。不执行真实 QQ、付费模型、生产数据库或部署脚本。
- 暂存文件后，人工阅读 `git diff --cached`，运行 `git diff --cached --check` 与 `node tools/audit-staged.mjs`；扫描通过仍需人工复核。
- PR 写明问题、结果、证据基线、已执行检查、未验证项和仅文档范围；更新证据文档中的日期与待确认清单。

## 检查触发方式

目前按用户请求或明确工程交接触发维护，没有配置 README 后台定时任务。若将来需要定期监测，先提交具体频率、只读检查范围、通知条件和文档 PR 流程，经用户授权再配置。不得在没有真实调度时承诺自动持续更新。
