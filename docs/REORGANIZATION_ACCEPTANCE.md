## 新协作者的最短接手路径

1. 从 [README](../README.md) 进入，阅读[当前状态](CURRENT_STATE.md)、[职责](MODULE_OWNERS.md)与[接口](INTERFACE_CONTRACTS.md)，确认任务范围和活跃分支。
2. 独立克隆或工作树，运行 `npm run check`；按任务修改基础源码或运行覆盖，新增源码先暂存。
3. 需要模块包时按[构建说明](MODULE_BUILD.md)使用全新输出目录，阅读 manifest；产物、公开模板与在线运行环境分别处理。
4. 同步 README 影响和对应证据页，经 PR 留下验证、限制、下一接任入口；不依赖聊天消息作为唯一交付。

## 不纳入“目录整理完成”的外部条件

- 后续对话、共同所有者与空间功能由成果负责人在 PR #25 接续，仍有独立验收与合入流程。本次固定包不覆盖更晚的运行代码。
- 集成、数据、发布及备份责任的具体接任人和 GitHub 身份尚待登记。QQ 管理身份不自动授予 GitHub 或设备权限。
- 完整生产组成、私有配置、依赖、备份恢复、回滚与接收侧效果须在授权环境交接；普通克隆不包含完整 Bot 安装与私人资产。
- 跨模块 SQL、双向存储访问与底层发送包装仍是明确的技术债，后续按契约逐项改进；本轮不声称消除全部架构耦合。
- 已发现标识清理不清除旧公开历史或他人副本，完整隐私和第三方权利仍需专项治理。仓库保持公开，未擅自添加统一开源许可。
