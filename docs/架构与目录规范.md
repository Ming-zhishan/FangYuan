# 方源 Bot 统一架构与目录规范（最终版）

## 运行链路

QQ 客户端 → NapCat / OneBot → DSH NEXT → Aurabot 自定义模块 → 方源人格/记忆/原著检索 → 模型网关 / Ollama / 云端模型。

**实目录（E 盘）：**

- `services/qq/work/`：NapCat、Ollama、本地模型、云网关、Python 虚拟环境、QQ 生产配置。
- `services/dsh/work/dsh-runtime/`：Aurabot 生产配置、学习/记忆数据库、运行日志与贴图。
- `services/dsh/work/fangyuan-dsh/`：原工程真实源码和原嵌套 Git 历史（仅本机保存）。
- `services/dependencies/dsh-next/`：DSH NEXT 程序依赖副本。
- `research/media-catalog/`：语音、表情包、研究和生成素材。
- `src/`：开发协作源码快照，**不自动同步到生产**。
- `archive/migration-recovery-20261031/`：迁移前恢复数据，包含敏感配置，禁止提交。

**内部目录联接：**

- `runtime/qq-stack/` → `services/qq/work/`
- `runtime/dsh-live/` → `services/dsh/work/dsh-runtime/`
- `operations/legacy-tools/` → `services/dsh/work/`
- `archive/legacy-releases/` → `services/dsh/outputs/`

目录联接不是副本，清理 `runtime` 内的文件就是修改真实数据。生产脚本通过 E 盘服务目录及兼容入口工作；不需要把 Windows 全局环境变量改成新的路径。

## 变更流程

1. 在 `src/` 修改和测试代码。
2. 用 `operations/check-source-drift.mjs` 只读对比实时部署差异。
3. 审核影响范围并备份对应配置与数据库。
4. 在明确的维护窗口部署改动，再检查 QQ、端口、生产保护与数据库状态。

最终验收与具体迁移路径见 `docs/物理迁移与运行验收_2026-10-31.md` 和 `docs/迁移与兼容性说明.md`。
