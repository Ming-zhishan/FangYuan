# 方源 Bot 多媒体研发铁则｜2026-10-31

**效力：** 本文件是后续方源 Bot 语音、表情包、GIF、图文二创及相关 QQ 接入工作的长期工程约束。任何后续任务、AI 助手、独立分支、自动化任务与生产部署都应先阅读并执行；与旧版实验手记或临时任务说明冲突时，以用户最新授权和本文件中更严格的生产保护条款为准。

## 01. 产品聚焦与实际目标
- 当前仅主攻 **A. 私聊语音表现** 和 **B. 表情包/GIF 选用与制作**。优先完成质量、真实效果、可用性和自然表达；不以新增插件数、素材数或模型调用量作为绩效。
- 群聊已暂停：生产 `allow.groups=[]`，不得因为开发新功能恢复群回复、群发、群戳一戳、群主动发言、从群收集表情或其他群消息。
- 不重写 DSH NEXT、Aurabot、NapCat/OneBot、TTS、人格核心或记忆系统。先梳理实际已存在模块、接口和开发成果，再做最小改动。

## 02. 证据分层：禁止夸大完成度
- 使用四级状态：**研究资料** → **已制作实物** → **离线测试通过** → **实际部署及指定私聊验收通过**。每一条状态须有可定位路径、日期、具体证据与验收标准。
- 旧对话或看板提到的“412段台词 / 286段可制作 / 80张表情 / 全部完成”等属于待重新核对的历史记录，不能直接覆盖最新源码、文件数量、媒体验收和生产状态。
- 不把路径存在当成功能实现，不把合成文件可播放当成 QQ 发送成功，不把素材数据库的候选项当作可上线媒体，不把模块加载成功当作真实功能可用。
- 不编造源视频、音频授权、原著章节、配音者身份、测试结果、生产日志、真人主观评价或真实发送回执。

## 03. 表情包与 GIF：已定制作标准
- 目标是 **高保真原梗 + 恰当的聊天语境**，而非大量新画的通用方源贴纸。优先真实来源、近期热梗与经典梗；已确认的规划参考为近期约 70% / 经典约 30%，随实际素材质量调整。
- 主视觉关注“不是哥们”类真实形象/语境。人像可少量方源化，但必须保留母版的镜头角度、姿态、情绪、服装背景、节奏、笑点；无法保持则不改。
- 动物、玩偶、包装、纯文字等非人物梗图只按原图存储，不擅自替换成方源脸；GIF 必须核对帧数、时长、动作与首尾状态。
- 候选、授权待核、已入生产库存分层；按哈希去重，记录来源和使用范围；标签需能在真实私聊语境下正确触发。保留语义选图安全闸门及严肃话题不发图策略。
- 当前参考基线是 **V4：32 张生产库存、8 份已核实原始媒体、4 份人像模板研究、62 项审核台、45 项相关测试**，其后续变化以新验收为准。

## 04. 语音：现有链路优先、授权硬门槛
- 先复用 Aurabot 现有语音、`voice.speak` 和 `normalizeVoiceEnvelope`；尊重已验证的 QQ 私聊播放能力，不重复搭 TTS。
- 现有语音研究资产：49 视频来源候选、11 份研究音轨、409 时间片、14 条精选文字，以及通用男声 TTS 样本。它们不是默认可发的语音包。
- 核查人物说话者、语录出处、原著上下文及引用长度；旁白、二创、角色台词不得混作方源本人所说。
- 对没有授权的配音、原音轨、音乐或真人音色克隆，**禁止进入生产自动发送**；取得特定声音克隆许可前，不以任何拟声方式冒称真人配音者。
- 正常短句、激动/讽刺/哲思等语气需重视可懂度、延迟、播放效果和表达时机；普通 TTS 不等于目标角色音色。
- Windows Kangkang 未安装，已有 Git 分支 `fix/voice-capability-fallback`；合并或部署前需核对最新生产代码，防止覆盖已有更改。

## 05. 工程过程：审计 → 设计 → 隔离开发 → 验证 → 灰度 → 交付
1. **建立基线**：只读审计实际生产版本、启用开关、运行日志、原有测试和 Git 分支；记录原文件 SHA-256、部署前配置与引用路径。确认正在运行的 Bot 不会被编辑动作意外影响。
2. **任务范围和验收点**：明确本次改动属于哪个模块、制作什么可检查的实物、具体何时算通过；避免范围外顺便大改人格、记忆、QQ 登录或模型配置。
3. **独立工作区**：优先使用 `<COLLAB_REPO>` 的 Git 功能分支/工作树或 `<MEDIA_RESEARCH_ROOT>` 的独立实验目录；绝不直接在生产目录调试模型/生成素材；源文件与镜像模块的同步关系要说明。
4. **测试**：对语义选图、音频编解码、消息封装、门禁、冷却、去重、权限、异常回退做离线自动测试；质量类另有可视/可听比对和人工复核。不得默认调用付费模型或向 QQ 发送测试消息。
5. **安全与性能**：分离配置模板与本机绝对路径，不在 Git 上传 QQ 号、Cookie/Token、原始私聊、学习库、数据库、受限媒体及未授权作品。控制 Token、素材体积、延迟和后台资源。
6. **受控部署**：每次生产改动单独授权，先备份原件与配置，先小范围灰度；验证热重载/进程/实际发送渠道是否成功。QQ 真实语音或图片只给明确许可的私聊目标做低频单项验收；绝不在群里测试。
7. **回滚**：保留原文件、配置与恢复说明；不重建/覆盖生产记忆、学习 SQLite、QQ 数据、聊天历史与他人新增素材；避免强推改写共享 Git 历史。
8. **收尾铁则**：确认成品可用、回滚备份存在、验收记录齐全后，主动清理本次临时下载、缓存、重复版本、无用半成品与测试产物。**不清理**唯一母版、研究证据、不可重建媒体、配置密钥备份、生产数据、必要源码和审计日志；对不确定归属的文件先保留并报告。
9. **交付格式**：写明版本/日期、功能清单、源素材及来源、已执行的测试和真实结果、未验收项、重要风险、生产改动、回滚位置与下一阶段。标注唯一“最终版”，避免多个互相矛盾的“最终验收”并存。

## 06. 现有目录与治理优先级
- 当前生产：`<AURABOT_PRODUCTION_ROOT>`，除明确授权的配置与部署外只读。
- 独立媒体研究：`<MEDIA_RESEARCH_ROOT>`；表情专项：`meme_pipeline_lab`；声音实验：`voiceclone_lab`。
- Git 协作：`<COLLAB_REPO>`；多媒体实物及研究原音不得因为方便协作而直接进公开 Git。
- 以 V4 表情验收、`全项目_自主总验收_最新.md`、实际配置及最新运行证据为起点；旧看板作为待核历史线索。
- 当前首要缺口：**表情的高保真人像成品与私聊自然发送验收；语音的具体音色品质、原著内容授权和正常私聊的单条实测**。未解决前不以数量扩张替代质量。

## 07. 个人体验约束
- 方源不是“展示功能的机器”。语音、表情都只在恰当语境出现，不自动附加、不刷屏、不抢重大话题、不为炫技反复发。
- 自主 QQ 说说的 14 天冷却、签名的 30 天冷却、当前仅私聊策略继续维持；后续多媒体研发不得意外覆盖这些近期生产改动。

## 08. 多协作者隔离与变更所有权铁则（2026-11-01 增补）

**强制适用**：方源系统存在多个并行协作者和自动化任务。本媒体研发职责只覆盖语音、表情包及各自独立的素材研究与质量验证。查阅其他模块不授予写权限。

1. **范围白名单**：每轮任务先记录模块负责人、任务名称、只读输入、允许写入的独立目录、Git 分支、基线哈希、验收条件。没有列入本任务白名单的文件，默认只能读，不能改。
2. **不碰他人的工作**：禁止顺便修改、重启或清理方源人格、记忆、关系学习、成本治理、QQ 网关、模型网关、定时调度、其他协作者工作树及系统配置。确需接口变化时仅提交接口契约或独立补丁，交由对应负责人集成。
3. **隔离开发和主分支保护**：新代码使用唯一独立工作树、分支和实验目录；不在生产根目录试错，不覆盖共享 main，不推送/合并他人的修改，不强推。提交前核对工作树干净与待提交文件清单；审计报告存在独立私有审计目录。
4. **同资源单写者**：语音来源 JSONL、表情 SQLite、研究原媒、视觉审核台、生产图库索引和专用自动化可能同时被其他任务访问。任何写入前必须确认唯一写者与锁/租约机制、目标基线哈希和冲突处理。锁机制缺失时不得竞争写共享文件，只在隔离副本生成候选与变更方案；不能删除其他人的锁或临时文件。
5. **旧路径门禁**：历史 C 盘路径现在可能通过重定向有效，但不能据此当成持久生产路径。执行会写入的旧脚本前，必须逐项解析到当前规范的 E 盘根，检查源/目标身份和哈希、脚本潜在删除/写配置/热重载副作用，并先在隔离副本测试。路径存在不构成执行授权。
6. **生产与对外行为独立授权**：不擅自部署、自动入库、训练声纹、发送 QQ、调用付费模型、提升语音/表情自动概率、恢复群聊或扩大联系对象。保持当前仅私聊、群白名单为零、语音与表情自动概率均为零，除非用户批准具体生产批次和测试目标。
7. **接口边界**：媒体侧仅交付来源和许可状态、经验证素材、可读标签、SHA-256、格式与时机建议、离线测试和回滚计划。正式发送由 Aurabot 的既有适配器与指定负责人受控集成；不得绕过原人格与隐私保护逻辑。
8. **发现冲突立即停止写入**：目标文件在开始后变化、Git 工作树异常、定时任务运行中、SQLite/WAL 正在被别的写者使用、来源许可不明、脚本指向的根发生变化时，保留现场并报告。禁止覆盖、强制 reset、重写共享历史和删除他人生成物。
9. **清理仅针对本任务产物**：验收通过后只清理自己创建、可重建、无保留价值的中间物；原版母图、研究音轨、模型试验数据、授权声明、历史 QA、备份、SQLite/WAL、他人文件及生产日志都不能自作主张清理。
10. **自动化同等遵守**：ChatGPT 定时任务、Work、Codex、远程工具和人工协作者同样应使用独立工作区、唯一写者、差异审计和生产授权。不能以计划中的目标或历史权限替代当前许可。
11. **当前阶段冻结生产**：仅开展表情包与语音生产/更新流水线只读审计、方案整合及非生产文档维护；任何新素材批量制作、克隆训练、目录迁移、热重载或生产导入，须在方案经用户讨论确定后另行执行。
